# Contributing

Thank you for considering a contribution to CoWork-OS.

## Contribution Principles

- Keep the core tool-agnostic.
- Use generic, public-safe examples.
- Do not include private names, local paths, secrets, customer data, or operational identifiers.
- Keep workflows audit-friendly and approval-driven.
- Prefer small, reviewable changes.

## Contribution Flow

1. Open an issue or describe the proposed change.
2. Explain the public value.
3. List affected files.
4. Run the public release review in `reviews/public-release-review.md`.
5. Submit a pull request with a concise summary and verification notes.

## Content Safety

Do not contribute:

- private handoffs
- private memory
- real project records
- credentials
- `.env` values
- production URLs or internal domains
- copied private repository history

Synthetic examples are welcome.
